MEASUREMENT BEFORE CLAIMS
What this lab measures
A small, repeatable environment for practicing database decisions.
01 / ENGINE
Real SQL, on your device
The official SQLite WebAssembly engine runs in a Web Worker, so queries execute separately from the interface. The database lives in memory and is rebuilt when you reload. No server or account is required.
This is SQLite, with EXPLAIN QUERY PLAN. It does not report MySQL EXPLAIN ANALYZE results, actual rows scanned, or production performance.
02 / METHOD
Repeated, warmed samples
Each comparison uses seven samples per variant in alternating order. Every sample gets one unrecorded warm-up after its schema is set. Timings include statement preparation, execution, and materializing all returned rows.
Index construction, ANALYZE, hashing, rendering, and worker messaging are excluded. Index creation time is reported separately, including ANALYZE. Timer precision, browser load, and in-memory caching affect results.
03 / CORRECTNESS
Fast is useful when answers match
All column names and typed row values are compared, retaining duplicates and ignoring row order. SHA-256 fingerprints are included in exported reports. A different row order alone passes; a different answer fails.
This check proves equality only for this generated dataset. It cannot prove two queries equivalent for every possible input.
04 / TRADEOFFS
An index has a cost
Indexes consume space and add write work. The lab reports occupied SQLite pages and measured index creation time, but does not benchmark inserts, concurrency, disk I/O, network delay, or a production server.
Plans can change with engine versions and data. Read the raw plan rather than assuming every scan is bad or every index is better.
